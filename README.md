# 深渊试炼 · Abyss Trial

回合制属性成长战斗小游戏。杀掉一头怪物 → 三选一强化 → 迎接下一波，直到倒下。
纯前端、零依赖、零构建，双击 `index.html` 即可游玩。

## 玩法

- **攻击**：常规输出，伤害 = 攻击 − 目标防御（带 15% 保底）
- **防御**：按防御属性换护盾（`8 + 防御 × 2.4 + 壁垒甲加成`），护盾上限为生命上限的 50%，不防御的回合衰减 30%
- **升级**：每波胜利后固定三张属性卡（生命 / 攻击 / 防御各一张），稀有度独立随机
- **战利品**：击杀后怪物身上的**每一件**装备都会掉落，逐件决定去留；全部处理完才能选属性卡
  - 空槽位 → 直接装备
  - 同款装备 → **吸收强化**（Lv+1，满 Lv.5 后转为升华，稀有度 +1 并重置 Lv.1）
  - 不同款 → 可**替换**（旧装备丢弃），也可以放弃
  - 还有剩余件数时头部会出现「全部放弃」，一次清空
- **装备**：4 部位（武器 / 护甲 / 头盔 / 饰品）× 3 件，五档稀有度，可升到 Lv.5 后升华
- **怪物**：第 1 波带 1 件装备，之后每 4 波多一件（最多 4 件）；血量首次跌破 50% 与 25% 时各举盾一次（不会连续举盾）；每 5 波是 BOSS

### 无随机战斗

战斗结算里**没有任何概率判定**，同样的属性与操作必定得到同样结果：

- **伤害恒定**：`攻击 − 目标防御`（15% 保底）后按减伤 / 破甲折算，不掷浮动
- **暴击是节拍**：裂风刃给的是「每第 N 次攻击必定暴击」，不是百分比。详情面板会显示「还差几击」
- **怪物 AI 由血线驱动**：跌破 50% / 25% 各举盾一次，玩家可以提前算清它这回合会不会怂

随机只留在**非战斗**环节：属性卡的稀有度、怪物携带的装备款式、怪物名字。这几项决定每局开局的差异，但不会在战斗中途掷骰子。

快捷键：`空格/回车` 攻击、`D/F` 防御、`R` 重开、`Esc` 关闭详情面板。

## 目录结构

```
index.html                 仅结构：卡片、弹窗、详情面板的 DOM 骨架
css/
  base.css                 重置、主题底色、背景层、应用骨架
  battle.css               顶栏、角色卡（头像/血条/护盾条/属性/装备栏/状态）、VS 区
  hud.css                  BOSS 进度点、操作按钮
  effects.css              伤害飘字、动作动画
  overlay.css              升级三选一、结算弹窗、波次横幅
  inspector.css            属性 / 装备详情面板
  responsive.css           窄屏与矮屏适配（最后加载，便于覆盖）

    config.js              所有数值：属性成长、怪物曲线、装备定义、词库
    utils.js               $ / sleep / pick / clamp / fmt

  systems/
    equipment.js           装备实例、属性聚合、战力重算
    state.js               全局状态与单位工厂

    monster.js             按波次生成怪物与随机装备（怪物装备同时是掉落来源）
    loot.js                战利品列表：逐件判定 装备 / 吸收强化 / 升华 / 替换 / 放弃
    cards.js               纯属性三选一卡池与交互
    flow.js                回合时序、波次推进、胜负判定
  ui/
    dom.js                 集中缓存 DOM 引用
    render.js              血条 / 属性 / 装备栏 / 状态 / 按钮
    fx.js                  飘字、冲击、横幅
    inspector.js           详情面板：基础值→装备→合计、词条、对抗预估
  main.js                  事件绑定与启动（必须最后加载）
```

模块之间**不互相 import**，全部挂到 `window.ABYSS` 命名空间上，靠 `<script>` 顺序解决依赖：

```js
(function (G) {
  'use strict';
  const { CFG, clamp } = G;      // 依赖在加载时解构，所以被依赖的模块必须排在前面
  function foo() { /* ... */ }
  Object.assign(G, { foo });     // 对外暴露
})(window.ABYSS = window.ABYSS || {});
```

这样既能分文件维护，又不需要打包器，`file://` 直接打开也不会被 ES Module 的 CORS 策略拦住。

## 调整数值

改 `js/core/config.js` 一处即可，不用碰其它文件：

| 字段 | 作用 |
| --- | --- |
| `player` | 初始生命 / 攻击 / 防御 |
| `attr` | 三种属性的五档升级值（白→金） |
| `mon` | 怪物成长曲线：`hp0/hpK/hpQ` 生命、`atk0/atkK/atkQ` 攻击、`def0/defK` 防御、`bossHp/bossAtk` BOSS 倍率、`eqBase/eqEvery/eqMax` 装备数量、`rarK/rarUpEvery` 装备稀有度成长（每 N 件升 1 档）、`bleedMul` 流血强度 |
| `loot` | —（已移除：怪物身上有几件装备就掉几件，件数由 `mon.eqBase/eqEvery/eqMax` 决定） |
| `heal` | 每波战后回复（有上限，避免滚雪球） |
| `defend` | 护盾公式、上限百分比、未防御时的衰减 |
| `rage` | 单场超过 N 回合后怪物每回合增伤，防止无限僵持 |
| `forge` | 装备强化等级上限 |

装备词条在 `ITEM_DEFS` 里，`stat` 是各稀有度的基础属性，`step` 是每级追加，`mk(r, L0)` 算出具体效果，`desc/tag` 负责文案。

## 平衡基线

用真实游戏代码跑批量自动对局（随机选属性卡、战利品能装就装、脚本按 12% 概率替玩家决定防御）的统计。
这里唯一的概率来自**自动对局的驾驶策略**，游戏本身的战斗结算是确定的。
为避免按局数抽样波动，脚本用固定随机种子（`mulberry32`）给每局喂牌序，同一组 24 个种子可直接横向比参数：

| 指标 | 结果（24 局，固定种子） |
| --- | --- |
| 中位波数 | 20 |
| p10 / p90 | 11 / 30 |
| 平均 | 20.5 |
| 每波回合 | 6.5 |

改完数值建议同样跑一遍批量对局，确认中位仍落在 18~22 波区间。

> **改为无随机战斗后的重调**：暴击从「百分比触发」变成「每 N 击必定触发」（同为均值，但方差归零），
> 怪物从「残血时 40% 概率防御」变成「50% / 25% 血线各举盾一次」，玩家挨的盾变少、活得更久，
> 中位从 18 抬到 25。把 `hpK 12.5→14`、`atkK 1.55→1.7` 后回到中位 20。
> p10 因此从 13 降到 11（撑不过第 10 波 BOSS 的局变多），但 p90 也从 25 抬到 30，整体分布更看构筑而不是运气。
>
> 历史：改动装备获取方式后玩家变强了很多 —— 卡池由「属性 + 装备」变成纯属性，等于每波都拿到 100% 的属性成长，
> 且每波白嫖装备。原先的中位是 21 波，改成纯属性卡后一度冲到 131 波。
> 让战利品从「随机 1 件」变成「怪物装备全掉」之后中位又涨到 30，
> 最终把怪物曲线持续上移（`hpK 9→12.5→14`、`atkK 1.3→1.55→1.7`）。
> 调平衡时优先动 `mon.hpK`（决定战斗回合数 → 决定玩家掉血速度），`atkK` 是第二杠杆。

## 部署

线上地址：<https://game.cat21432961.online>

部署形态与 `mailhub` / `book` 一致：**Cloudflare Workers**（静态资源 Worker，没有 `main` 入口，`[assets]` 直接托管 `dist/`），
不再使用 Cloudflare Pages。Worker 名 `game`，自定义域名由 `wrangler.toml` 的 `[[routes]]`（`custom_domain = true`）托管 DNS 与证书。

```bash
bash scripts/deploy.sh        # 生成 dist/ → 给资源加版本指纹 → wrangler deploy
```

脚本只拷贝 `index.html`、`css/`、`js/` 到 `dist/`（`.git/`、`.workbuddy/` 不会上传）。
首次在新机器部署需先 `npx wrangler login` 授权。

`wrangler.toml` 已固定 Worker 名与产物目录，也可以直接：

```bash
npx wrangler deploy
```

> 从 Pages 迁到 Worker 时踩过一个坑：`game.cat21432961.online` 当时已有一条指向 `abyss-trial.pages.dev` 的 CNAME，
> Workers 会报 `100117 …already has externally managed DNS records`。必须先删掉那条旧记录，
> 再 `wrangler deploy`，自定义域名与证书由 Workers 自动接管。
